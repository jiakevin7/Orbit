# Orbit Dataset Guide

Orbit's mixed realistic workload is split into four traffic families:

- chat: multi-turn conversational prompts with repeated system and session history
- rag: retrieval-heavy prompts with long quoted context blocks
- agent: tool-using prompts with API schemas, policies, and intermediate tool state
- bursty: short-lived surges built from session-correlated chat traffic

## Current External Inputs

Orbit can already ingest three external dataset paths:

- `--sharegpt-path`: ShareGPT-style chat JSON or JSONL
- `--rag-path`: retrieval-style JSON or JSONL
- `--agent-path`: agent or tool-use JSON or JSONL

Bursty traffic is generated by resampling session-local arrivals from the chat pool, because most public datasets do not expose production-grade request timestamps.

## Formats Orbit Accepts Today

The current loaders in [orbit/workload.py](/Users/baseb/Documents/6th Year/CSE 585/Orbit/orbit/workload.py) handle these common shapes without a custom adapter:

- chat:
  - `conversations`, `messages`, `turns`, or `conversation`
  - message role fields such as `from`, `role`, or `speaker`
  - message text fields such as `value`, `content`, or `text`
- rag:
  - query fields such as `query`, `question`, `input`, `prompt`, or `instruction`
  - context lists such as `quotes`, `contexts`, `documents`, `docs`, `retrieved_contexts`, or `evidence`
  - context text fields such as `text`, `content`, `document`, or `evidence_text`
- agent:
  - chat-like message lists plus `tools`, `functions`, `available_tools`, or `api_list`
  - single-turn query records with tool metadata

That makes the following sources either directly usable or one small field rename away.

## Recommended Sources

### Chat / Session Locality

- ShareGPT-X
  - Best fit for repeated conversational prefixes and multi-turn chat locality.
  - Orbit has already been exercised against a local sample from this family.
- LMSYS-Chat-1M
  - Good for real public chat traffic distributions and language diversity.
  - Its `conversation` field now loads directly.
- UltraChat
  - Useful when you want broad conversational coverage without depending on public-share artifacts.
  - Better for scale than for true production locality because it is largely synthetic.

### RAG / Long-Context Retrieval

- RAGBench
  - Good general RAG corpus with multiple subsets and groundedness annotations.
  - Orbit has already been exercised against a local `hotpotqa` sample.
- HAGRID
  - Good for attributable generative retrieval because it includes quoted supporting passages.
  - The `quotes` structure fits Orbit's current RAG loader well.
- LongBench
  - Good for long-context and multi-document stress tests, especially when you want much longer reusable prefixes.
  - Its `input` plus `context` layout is already compatible with Orbit's loader.
- FinanceBench
  - Good domain-specific RAG workload with grounded evidence spans over SEC filings.
  - Orbit now accepts FinanceBench-style `evidence` records directly.

### Agent / Tool Use

- ToolBench
  - Good broad API-tool corpus with explicit tool descriptions and tool-oriented instructions.
  - Orbit has already been exercised against a local sample from the official `G1/G2/G3` query files.
- BFCL
  - Good for function-calling coverage, especially multi-turn and multi-step tool invocation.
  - Orbit now accepts BFCL-like `question` plus `function` records directly through `--agent-path`.
- tau-bench / tau2-bench
  - Good for customer-support and enterprise-style conversational agents where policy, tools, and user turns interact over time.
  - Orbit now accepts tau-bench-like task and trajectory records directly through `--agent-path`.
- AgentBench
  - Useful as a benchmark family for environment-facing agents, though several environments need task-specific adapters before they look like prefix-routing traffic.
- Mind2Web
  - Useful for web-agent tasks with long action histories and rich state, especially if browser-state prefixes matter.
  - It needs an adapter because the raw benchmark is trajectory-centric rather than chat-schema centric.

### Bursty / Data Center Traffic Shape

- ShareGPT-X or LMSYS-Chat-1M with timestamp resampling
  - Best available public proxy for bursty conversational demand if you preserve conversation grouping.
- Internal serving traces
  - Best source when available, because public datasets rarely capture retries, cancellations, or true inter-arrival bursts.

## Practical Recommendation

If the goal is to make Orbit materially closer to production while staying lightweight, use this stack first:

1. ShareGPT-X or LMSYS-Chat-1M for chat and bursty traffic
2. RAGBench plus HAGRID or FinanceBench for retrieval-heavy traffic
3. ToolBench plus BFCL or tau-bench for tool-using agent traffic

That combination gives you:

- repeated chat prefixes
- long retrieved context blocks
- explicit tool schemas and tool-planning prompts
- more realistic variation in prompt length and session behavior

## Example

```bash
python3 scripts/benchmark_policies.py \
  --backend llama_cpp \
  --model /absolute/path/to/model.gguf \
  --workload-kind mixed_realistic \
  --sharegpt-path /absolute/path/to/sharegpt_like.json \
  --rag-path /absolute/path/to/rag_like.json \
  --agent-path /absolute/path/to/agent_like.json \
  --requests 40 \
  --warmup-requests 10 \
  --seeds 7 11 17 \
  --output-dir results/mixed-realistic-external
```
